# 🤸 Agile Practices

Agile is a set of values and technical habits, not a ceremony pack. Leaders protect adaptability
and feedback loops — and refuse “agile” process that ships without engineering discipline.

**Start here:** the Manifesto for intent, Fowler’s Flaccid Scrum for the common failure mode,
Beck’s XP when you need concrete technical practices behind the sticky notes.

## Resources

📄 [Manifesto for Agile Software Development](https://agilemanifesto.org/)  
The source values and principles — still the right reset when process has replaced outcomes.

📄 [Flaccid Scrum](https://martinfowler.com/bliki/FlaccidScrum.html) by Martin Fowler  
Why Scrum without technical practices produces messy code and mounting debt — process alone is
not agility.

📘 [Extreme Programming Explained](https://www.goodreads.com/book/show/67833.Extreme_Programming_Explained)
by Kent Beck and Cynthia Andres  
Concrete practices (TDD, pairing, continuous integration, collective ownership) that make
iterative delivery safe.

🎥 [Agile vs Scrum and Flaccid Scrum](https://www.youtube.com/watch?v=kxk3Kg7LofY) by Robert C.
Martin  
A blunt warning that Scrum rituals without XP-style engineering habits are not enough.

📄 [The Scrum Guide](https://scrumguides.org/scrum-guide.html) by Ken Schwaber and Jeff Sutherland  
The official definition of Scrum — useful as a reference, dangerous as a cargo-cult checklist.
