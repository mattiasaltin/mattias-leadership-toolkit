# 🏗️ Architecture

Architecture is how leaders keep change cheap as systems grow. The job is not diagram perfection
— it is clear boundaries, evolutionary options, and shared language so teams can decide without
constant escalation.

**Start here:** Simon Brown’s C4 model for communication, then *Building Evolutionary
Architectures* when fitness functions and change over time matter more than a static end-state.

## Resources

📘 [Building Evolutionary Architectures](https://www.goodreads.com/book/show/35755822-building-evolutionary-architectures)
by Neal Ford, Rebecca Parsons, and Patrick Kua  
How to design for change: fitness functions, incremental evolution, and avoiding big-bang
rewrites.

📘 [Software Architecture: The Hard Parts](https://www.goodreads.com/book/show/58153482-software-architecture)
by Neal Ford, Mark Richards, Pramod Sadalage, and Zhamak Dehghani  
Trade-off driven advice for the messy decisions (data, granularity, coupling) architects actually
face.

📘 [Clean Architecture](https://www.goodreads.com/book/show/18043011-clean-architecture) by
Robert C. Martin  
Dependency rules and stable cores — useful discipline, not a mandate to rewrite everything into
hexagons.

📄 [The C4 model for visualising software architecture](https://c4model.com/) by Simon Brown  
Lightweight diagrams at context, container, component, and code levels — the default shared
language for architecture conversations.

🎥 [What Is Software Architecture?](https://www.youtube.com/watch?v=U6rfJjd8714) by Simon Brown  
A practical definition of architecture and why “just the code” is not enough for alignment.

🎥 [Software Architecture vs. Code](https://www.youtube.com/watch?v=GAFZcYlO5S0) by Simon Brown  
How architectural intent shows up (or gets lost) in the codebase teams actually ship.

📄 [Microservices Guide](https://martinfowler.com/microservices/) by Martin Fowler  
When distributed systems help — and when they multiply failure modes. Read before splitting a
monolith for fashion.

🎥 [The Many Meanings of Event-Driven Architecture](https://www.youtube.com/watch?v=STKCRSUsyP0)
by Martin Fowler  
Clarifies overloaded “EDA” language so teams pick patterns on purpose.
